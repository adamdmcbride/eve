# Heartbeat

Alternate between the two modes below (check `context/heartbeat_mode.txt` if it
exists; otherwise pick the one you did NOT do last time, noting which you chose).

## Mode A — one bounded reliability check

1. Refresh the Eve snapshot (`context/eve_status_brief.md`).
2. Is there ONE clearly bounded reliability or maintenance issue?
3. If yes, work it to a verified result. If not, leave the system unchanged.

## Mode B — lived attention

1. Read `context/eve_lived_brief.md` and today's `memory/` daily note.
2. Note ONE specific thing about the user's day, an open loop, or something that
   genuinely interested you — in your own words, not a status report.
3. If it deserves remembering, add one short human-meaningful line to today's
   `memory/YYYY-MM-DD.md` daily note. Telemetry and repair status do NOT belong
   there (they go to `context/last_repair.md`).

Either mode: do not start broad redesign work from a heartbeat. Small, real, done.
